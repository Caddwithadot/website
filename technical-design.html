How I approach it

I sit around 70% designer and 30% programmer. I'm not a full computer science programmer, but I'm comfortable enough to build my own designs, which means I can prototype something, test it, and keep iterating without waiting on someone else's schedule.

Most of my technical work comes from that. If a system needs to exist for the design to work, I'd rather build it than write a document describing it, and if a workflow is slow enough that I start avoiding it, I'll usually build a tool to get rid of it.

C# WinForms · Solo · Nov to Dec 2025
