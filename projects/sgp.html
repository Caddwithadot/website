SGP: Streamer Game Project

Twitch-Integrated Interactive Prototype · Unity
Summer 2023Systems Designer & ProgrammerTeam of 2
SGP

Overview

After Project Nasu I spent the summer building a prototype with another designer called SGP, short for Streamer Game Prototype. The goal was to explore how Twitch chat could directly drive an in-engine Unity experience, treating the chat window as an input device rather than as a feed sitting next to the game.

The longer-term vision was an interactive playground where a streamer could move through the space with a spectator-style controller and interact with their community in real time.

Goal
Turn passive viewers into visible participants, so that sending a message in chat produces something the whole stream can see happen in the world.

Chat as an input device

I designed and implemented a system that instantiated avatars in the scene based on live chat activity from a connected stream. Each chatter spawns an avatar the moment they send a message, complete with a floating nametag tied to their username.

Every avatar has a lifetime timer, and when that same chatter sends another message the timer resets and triggers a small hop animation. That tiny bit of feedback is the whole idea in a nutshell. The system turns live chat activity into something you can actually watch happen, so a busy chat becomes a visibly busy crowd instead of a wall of scrolling text.

Representation

Avatar spawning and lifetimes

Avatars spawn from messages, with nametags pulled from usernames and lifetime timers running per chatter, so the crowd in the scene is a live picture of who is actually talking.

Networking

First-person chatter control

Prototyped networking that let chatters connect directly to the game and drive their own avatar in first person, moving the system from a visualization toward a shared space.

Persistence

Google Sheets as a data store

A public Google Sheet used as a persistent data store keyed by username, meant to support inventories, currency, and cosmetic unlocks. It's a pretty hacky solution, but it worked for what I needed.

Commands

Chat-driven customization

A "!color" command letting viewers change their avatar color, with values validated on input and saved externally so the change persisted across sessions.

Emote parsing

Toward the end of development I built a dynamic emote parsing system that detected emotes in chat messages and spawned particle effects using the emote image itself as the sprite, tied to whoever sent it. It's the feature I would most want to go back to, because it takes something viewers already do constantly and turns it into something visible in the world without asking them to learn anything new.

What I took from it

The full progression system never got finished, but the prototype covered a lot of ground I hadn't touched before. I worked with live data coming in from an outside service, built modular systems for representing players, and spent most of my time on feedback that both the streamer and the chat could follow in real time.

If a viewer can't see their own message do something, the whole integration may as well not be there.
