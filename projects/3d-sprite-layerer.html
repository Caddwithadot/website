Sprite Layerer

Overview

The 3D Sprite Layerer is a custom Unity editor tool I built over about three weeks to automate the creation of layered sprite prefabs. It was made for a 2.5D prototype where props are built out of stacked sprites arranged in 3D space, producing a paper-like depth effect.

Before the tool, building one of those props meant duplicating sprites, placing each layer by hand, and tweaking values one at a time. It worked, but it made every prop slow enough that I started avoiding making them, which is a bad sign when environment setup is supposed to be the quick part.

Goal
Turn a slow manual assembly process into a generated one, so building environment props stops competing with time spent on gameplay systems.

What it does

You give the tool an array of sprites and it generates a finished prefab, handling the layer placement in 3D space for you. Everything about how those layers sit relative to each other can be configured, so the same set of sprites can produce pretty different looking props.

Layout

Spacing, angles, and ordering

Configurable spacing between layers, per-layer angles, and draw ordering, which together control how strong the stacked paper effect looks from any given camera angle.

Variation

Random offsets and variants

Random positional offsets and variant generation, so a set of props built from identical sprites doesn't look copy-pasted across a scene.

Workflow

Save-location control

Define where the generated prefabs get saved, so output stays organized instead of ending up wherever the tool happened to run.

Collaboration

Built for artists

Designed so a future collaborator, particularly an artist, could import their own sprites and generate usable props without assembling anything in the scene by hand or knowing how the effect works.

Why it mattered

The point was getting time back. Cutting down environment setup meant I could stay focused on gameplay systems during early prototyping, which is where my time should have been going. Building it so artists could use it was the other half, since a tool only I know how to run isn't much of a tool.

The prototype it was built for eventually got shelved, but the tool still works and could be reused if we ever take another shot at a game in that style.

What I took from it

This was my first custom editor tool, and it set up the same pattern I followed with the Input Replay Analyzer a month later. Find the repetitive thing that's quietly shaping what you're willing to build, then get rid of it.

If a workflow is slow enough that I start avoiding it, that's a problem worth fixing with a tool.
